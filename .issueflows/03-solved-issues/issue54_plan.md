# Plan for issue #54: Allow for more interactive sessions

## Goal

Add an **interactive, iterative-fix workflow** to issue-flow: a single command
(`/issue-fix`) that sets up one long-lived branch + tracking issue, then runs a
loop where the user proposes small fixes one at a time, each getting a short
plan and (on confirmation) an implementation, with every fix recorded in the
issue's markdown. The session ends with the normal `/issue-close`.

## Constraints

- **Edit templates, not rendered output.** All scaffolded behavior comes from
  `src/issue_flow/templates/`. Never hand-edit the already-rendered copies under
  `.cursor/` (they are regenerated by `issue-flow update`).
- **Mirror the command/skill pattern.** Every slash command has a matching Agent
  Skill (portable core, emitted for every editor; commands only for editors with
  a `commands_dir`). New work must add **both** a `commands/issue-fix.md.j2` and a
  `skills/issueflow_issue_fix/SKILL.md.j2`, registered in `templating.py`.
- **GitHub only.** issue-flow's external-CLI surface is `git` + `gh`; GitLab is
  not supported. The owner's comment mentions "github/gitlab" but we implement
  GitHub via `gh` (note this explicitly; GitLab is out of scope).
- **Off-path command.** Like `/issue-pick`, `/issue-yolo`, and `/graphify`,
  `/issue-fix` must be **off-path**: never auto-dispatched by `/iflow`. It can
  create GitHub issues and branches, so it is explicit-only. Skill frontmatter
  sets `disable-model-invocation: true`.
- **Git safety norms.** Never create a GitHub issue or branch without explicit
  confirmation; never force-push or delete branches from this command; finishing
  delegates to `/issue-close` (and post-merge cleanup stays with `/issue-cleanup`).
- **Keep status-file checkbox convention.** Use `- [ ] Done` / `- [x] Done` so the
  existing sweep + `/iflow` logic continue to route the issue correctly.
- Follow `.issueflows/04-designs-and-guides/` conventions; record this new
  command's design decision there (see Files to touch).

### Prior art

- **`/issue-pick fix`** (`commands/issue-pick.md.j2`, `skills/issueflow_issue_pick`)
  — convention: creates a **new** `chore: general fixes` GitHub issue every time
  via `gh issue create`, branches `git switch -c <N>-<slug>`, delegates capture to
  `/issue-init`, hands off to `/issue-plan`. **Strong overlap** with issue #54's
  step 2 (create issue + branch). New work: *coexist* — `/issue-pick fix` is a
  one-shot "set me up on a fixes branch then use the normal flow"; `/issue-fix`
  adds the **interactive multi-fix loop** on top and ends at `/issue-close`. See
  Open questions for the merge-vs-coexist call.
- **`/issue-yolo`** (`commands/issue-yolo.md.j2`) — convention: an off-path
  *chain* with up-front preflight (default-branch refusal, dirty-tree refusal,
  consolidated confirm) that delegates to the lifecycle commands rather than
  re-implementing them. New work: mirror this "thin orchestrator, delegate to
  sub-commands, explicit confirms" style for the loop.
- **`/issue-init`** (`commands/issue-init.md.j2`) — convention: owns
  issue-number resolution, `owner/repo` derivation from `git remote`, the
  `.issueflows/01-current-issues/` archive sweep, and `issue<N>_original.md`
  creation. New work: *delegate* local capture to it instead of duplicating.
- **`/issue-plan` / `/issue-start`** — convention: plan→implement with explicit
  confirmation. New work: each loop iteration is a deliberately **lightweight**
  plan→implement (short per-fix plan, implement only if the user says yes),
  recorded in markdown rather than written as a full `issue<N>_plan.md`.
- **Manifest wiring** (`templating.py` `COMMAND_NAMES`, `SKILL_DIRS`,
  `build_manifest`) and **`docs/issue-workflow.md.j2`** lifecycle table /
  `rules/_body.md.j2` "Command lifecycle" / `README.md` — convention: every new
  command is enumerated in all four places plus the test suite. New work: add
  `/issue-fix` to each.

## Approach

1. **New slash-command template** `src/issue_flow/templates/commands/issue-fix.md.j2`.
   Structure (mirroring `issue-pick.md.j2` / `issue-yolo.md.j2`):
   - **Header**: off-path interactive command for iterative small fixes on one
     long-lived branch.
   - **Input**: optional proposed name/slug. If omitted, default the slug to
     something like `iterative-small-fixes` but ensure uniqueness (suffix the new
     GitHub issue number once known).
   - **Setup phase** (delegates where possible):
     1. Preflight: detect default branch, `git fetch --prune`, report current
        branch + clean/dirty tree.
     2. Confirm + create a GitHub issue with `gh issue create` (title from the
        proposed name, body explaining it is an iterative-fixes session). Capture
        the returned number `N`.
     3. Branch: if on default → branch off default (`git switch -c <N>-<slug>`);
        if on a non-default branch → **ask** whether to branch from the current
        branch or from the default. Confirm the branch name.
     4. Capture locally by delegating to the `/issue-init` flow for `<N>` (writes
        `issue<N>_original.md`, runs the archive sweep). Write an initial
        `issue<N>_status.md` with an **Iterative fixes log** section and an
        unchecked `- [ ] Done`.
   - **Loop phase** (the heart of the feature): repeat until the user stops —
     1. User describes a small fix.
     2. Agent writes a **short** plan inline (a few lines: intent + files), asks
        to proceed.
     3. On confirmation, implement; otherwise skip/revise.
     4. Record the fix as a dated bullet in the status file's **Iterative fixes
        log** (proactively offer to update; always update when asked).
   - **Finish**: tell the user to run `/issue-close` (do not auto-run it). Note
     `/issue-cleanup` after the PR merges.
   - **Constraints** block mirroring the other off-path commands.

2. **New skill** `src/issue_flow/templates/skills/issueflow_issue_fix/SKILL.md.j2`
   — frontmatter `name: issueflow-issue-fix`, `disable-model-invocation: true`,
   description summarizing the interactive loop; body mirrors the command.

3. **Register in the manifest** (`src/issue_flow/templating.py`):
   - add `"issue-fix"` to `COMMAND_NAMES`,
   - add `"issueflow_issue_fix"` to `SKILL_DIRS`.
   This bumps the cursor manifest 25 → 27 and the codex manifest 14 → 15.

4. **Make `/issue-fix` visible but off-path** in the dispatcher + rules:
   - `commands/iflow.md.j2` + `skills/issueflow_iflow/SKILL.md.j2`: list
     `/issue-fix` among the explicit-only, never-auto-dispatched commands, and
     note that an active `/issue-fix` session is driven by `/issue-fix` +
     `/issue-close` (not `/iflow`, which would otherwise see "no plan file" and
     dispatch `/issue-plan`).
   - `rules/_body.md.j2` "Command lifecycle": add a short paragraph for
     `/issue-fix` (alongside the `/issue-yolo` note).

5. **Docs**: update `docs/issue-workflow.md.j2` — bump "ten … slash commands" to
   "eleven", add a table row + skill row + a numbered section for `/issue-fix`,
   and add it to the "Detours" block. Update `README.md` (tree listing, skills
   list, prose) to mention `/issue-fix`.

6. **Design doc**: add `.issueflows/04-designs-and-guides/issue-fix-interactive.md`
   capturing the decision (coexist with `/issue-pick fix`, off-path, GitHub-only,
   per-fix log in the status file) and alternatives considered.

## Decisions (resolved 2026-06-16)

1. **Command name** — **`/issue-fix`** (confirmed).
2. **GitHub issue** — **always** create one via `gh issue create` (no local-only
   mode in v1).
3. **Fix log** — record each fix as a dated bullet under an **Iterative fixes log**
   section inside `issue<N>_status.md` (no dedicated `issue<N>_fixes.md`).
4. **Relationship to `/issue-pick fix`** — **coexist**: `/issue-fix` is the
   interactive loop ending at `/issue-close`; `/issue-pick fix` stays the one-shot
   setup into the normal flow.
5. **`/iflow` during a session** — **document only** that an active `/issue-fix`
   session is driven by `/issue-fix` + `/issue-close` (no status marker / `/iflow`
   detection in v1).
