# Plan: #211 — option C problem

## Goal

Make `issue-flow agent sweep` accept `-C` / `--project-dir` the same way
`agent capture` already does, so the multi-root init chain
(`capture … -C <root> && sweep --except N -C <root>`) stops failing with
`No such option: -C`. Align other leftover `agent` subcommands that still take
a positional project dir with that same `-C` contract (skills already tell
agents to pass it).

## Constraints

- **Root cause (not title):** issue text blames `capture -C`, but the pasted
  log shows **capture succeeded** and **`sweep` rejected `-C`**. Fix the CLI
  mismatch; do not “add `-C` to capture” (already present).
- **Contract:** `_resolve_project_root` + `iflow-init` skill already document
  `sweep … -C <project_root>` and “pass `-C` to other `issue-flow agent …`
  subcommands”. CLI must match docs, not the reverse.
- **Source of truth:** edit `src/issue_flow/cli.py` (+ tests/docs). Scaffolded
  copies under `.cursor/` are regenerated by `issue-flow update`; skill
  templates already show `-C` for sweep — no template wording change required
  for the reported failure.
- **Back-compat:** switching sweep from positional `PROJECT_DIR` to
  `--project-dir/-C` matches `capture`/`archive`/`resolve`. Callers using
  `agent sweep <path>` (tests today) must move to `-C <path>`. Acceptable —
  agent skills never documented the positional form with a path.
- **Out of scope:** top-level `init`/`update`/`status`/`doctor` stay positional;
  no behavior change inside `run_sweep` / tracking logic.

### Prior art

- `agent capture` / `archive` / `resolve` / `epic-status` / `queue` /
  `label-*` / `config add` — already
  `typer.Option(..., "--project-dir", "-C", …)` in
  [`src/issue_flow/cli.py`](src/issue_flow/cli.py).
- `agent sweep` / `state` / `preflight` / `switchback` / `branches` /
  `version-plan` / `audit` / `repair` — still `_PROJECT_DIR_ARGUMENT`
  (positional).
- Skill docs already assume `-C` for sweep
  ([`iflow_init/SKILL.md.j2`](src/issue_flow/templates/skills/iflow_init/SKILL.md.j2))
  and branches
  ([`iflow_cleanup/SKILL.md.j2`](src/issue_flow/templates/skills/iflow_cleanup/SKILL.md.j2)).
- Design: [`.issueflows/04-designs-and-guides/agentic-cli.md`](.issueflows/04-designs-and-guides/agentic-cli.md),
  [multi-repo-workspaces.md](.issueflows/04-designs-and-guides/multi-repo-workspaces.md).
- Tests: [`tests/test_cli.py`](tests/test_cli.py) — sweep/state invoke with
  positional path; capture/archive already use `-C`.

## Approach

1. Add a shared `_PROJECT_DIR_OPTION` (mirror existing Option kwargs on
   `capture`: default `.`, `exists=True`, `file_okay=False`, `resolve_path=True`).
2. Convert every `agent_*` command that still uses `_PROJECT_DIR_ARGUMENT` to
   that Option: **sweep** (must), plus **state**, **preflight**, **switchback**,
   **branches**, **version-plan**, **audit**, **repair** (same latent bug;
   `_resolve_project_root` claims all agent cmds take `-C`).
3. Leave top-level `status` / `doctor` / `init` / `update` on the Argument form.
4. Update tests that pass a bare path to those agent commands → `-C <path>`;
   add one smoke assert that `agent sweep --help` documents `-C` /
   `--project-dir`, and that `agent sweep --except N -C <tmp>` works (the
   failing recipe from the issue).
5. Update [`docs/cli.md`](docs/cli.md) synopsis lines for the converted agent
   commands (`[PROJECT_DIR]` → `[-C PROJECT_DIR]`).
6. Optional one-liner in `agentic-cli.md`: agent subcommands take `-C` like
   capture (keep durable).
